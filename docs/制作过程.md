# 美国硕士选校推荐 · 制作过程

> 这份文档记录了这个工具是**怎么一步步长出来的**，包括中途被推翻的方案、失败的抓取、以及几个差点毁掉项目的 bug。
> 写得比较细，因为"怎么做出来的"往往比"做成了什么"更有参考价值。

---

## 0. 起点

最初的请求只有一句话：

> "我想做一个项目，具体是做一个留学申请的准备工作汇总信息。"

没有任何约束：没有国家、没有交付形式、没有用户画像。所以第一版做的是**覆盖英美港新澳五国**的通用规划底稿，输出成一个单文件网页。

这一版后来被推翻了，但它定下了整条路线的技术底座：**单文件 HTML + 原生 JS + localStorage**（见第 9 节的技术决策）。

---

## 1. 第一轮：五国通用版（被推翻）

做了 8 个板块：总览、倒排时间线、五国对比、材料清单、选校矩阵、预算测算、语言标化、政策核实。

核心设计是**倒排时间线**：以目标入学月为锚点，用 `monthShift(y, m, -n)` 反向推算每个阶段落在哪个月，改入学季整条线自动重算。

**为什么被推翻**：用户说"只做美国学校的硕士申请，要求能够根据背景填写选出合适的学校推荐"。

五国版的价值是"广度"，但留学申请真正难的是"定位"——我该申哪几所。于是重做。

## 2. 第二轮：美国单国 + 推荐算法（核心设计）

这是整个项目最重要的部分。

### 2.1 数据结构

每个项目是一个对象：

```js
{s:"UIUC", p:"MS in Computer Science", city:"Urbana", st:"IL", reg:"midwest",
 ct:"小城", tuit:42000, liv:18000, dur:2, d:0.72, gpa:3.65, toefl:103,
 gre:"opt", ddl:"12/15", f:"cs", rk:33, note:"..."}
```

- `d` 是**难度分**（0–1），不是排名。排名只影响 `d` 的初始赋值。
- `gpa` / `toefl` 是该项目录取的中位数/门槛，用来算差距。

### 2.2 竞争力打分

**第一版**（只看标化，被推翻）：

```
竞争力 = 0.45×GPA + 0.30×语言 + 0.15×院校 + 0.10×GRE
```

问题很明确：它衡量的只是"考试竞争力"，而 CS / AI / DS 硕士真正看的是**科研项目**和**专业匹配度**——这两项在公式里根本不存在。跨专业申请者会被系统性地高估。

**第二版**（六维，当前采用）：

```
GPA       25%   clamp((GPA − 2.8) / 1.2, 0, 1)
科研与项目 25%   无 0.15 / 课程项目 0.35 / 实习项目 0.55 / 助研 0.72 / 论文或专利 0.90
专业匹配度 20%   CS 本科 1.00 / 相关专业 0.75 / 跨专业有先修 0.55 / 跨专业无先修 0.25
语言      10%   clamp((TOEFL − 79) / 41, 0, 1)
本科背景  10%   海本 0.95 / 985 1.00 / 中外合办 0.85 / 211 0.72 / 双非 0.42
GRE       10%   clamp((Q − 155) / 15, 0, 1)；未考按 0.50
```

### 2.3 难度 ≠ 录取概率

早期版本把难度分直接映射成"参考录取率 <10% / 10–20% / …"。这是错的：

**难度是项目的属性，录取概率是个人的结果。** 同一个项目对所有申请者难度相同，但每个人的录取概率不同。把二者画等号，会让用户误以为系统知道他的概率。

改成两个独立指标：

- **项目申请难度**：极高 / 高 / 中高 / 中等 / 较低（由难度分 `d` 映射，只描述项目门槛）
- **个人背景匹配度**：0–100（由"你的竞争力 − 项目难度"换算，只描述接近程度）

并在卡片上明确写："匹配度反映你的背景与项目要求的接近程度，不是录取概率。"

**第三版**（把"科研"和"匹配"拆成可核查的子项）：

六维版里这两项还是两个粗下拉，两个 GPA 3.5 / TOEFL 100 的学生选同一个选项就得到同一个分。改成由具体事实推导：

```
匹配分 = 0.45×编程（弱 0.25 / 一般 0.60 / 较强 0.95）
       + 0.35×数学覆盖（线代 0.30 + 概率 0.30 + 微积分 0.20 + 离散 0.20，上限 1.0）
       + 0.20×数据结构与算法（已修 1 / 未修 0）

科研分 = 0.35×论文（无 0.10 / 在投 0.45 / 已发表 0.75 / 顶会 1.00）
       + 0.25×ML项目（0 个 0.10 / 1 个 0.55 / 2+ 1.00）
       + 0.20×实习（无 0.15 / 1 段 0.55 / 2+ 0.85）
       + 0.20×推荐信（一般 0.35 / 较强 0.65 / 很强 0.90）
```

效果（实测）：同样 GPA 3.5 / TOEFL 100 / 985 的两个学生——

| | 编程 | 科研 | 匹配 | 总分 |
|---|---|---|---|---|
| 学生 A | 较弱 | 16 | 11 | **41** |
| 学生 B | 较强 + 已修 DS + 数学全修 + 2 个 ML 项目 + 已发表 + 1 段实习 + 推荐较强 | 75 | 98 | **73** |

差距 32 分，全部来自 GPA 和 TOEFL 看不见的东西。

换成六维后有个副作用：分数分布整体下移（同一个 985/3.6/100 的 CS 本科生从 0.65 掉到 0.65，但跨专业从 0.65 掉到 0.57）。所以冲刺窗口从 `−0.18` 收紧到 `−0.13`——否则差值 −0.19 的学校也会被塞进"冲刺"，而它们的实际录取率接近 0。

### 2.3 分档

```
差值 = 竞争力 − 项目难度 d
差值 ≥ +0.10   → 保底
−0.02 ~ +0.10  → 匹配
−0.13 ~ −0.02  → 冲刺（六维模型后从 −0.18 收紧）
< −0.13        → 不列出
```

另外两类扣分：

- 项目强制 GRE 而你没考：`−0.06`
- TOEFL 低于项目门槛：`−0.05`

### 2.4 缺档补位

第一版有个真实缺陷：弱背景用户只推出 2 个项目（库里没有更低门槛的学校）。改成**缺档时从相邻档补位**，但保底档只从"差值 ≥ −0.08"里补，绝不把冲刺校硬塞进保底。

这一条在测试里反复调过：3/4/3 的名单必须稳定，且"保底"名副其实。

### 2.5 为什么把算法摊开

用户后来提了"黑箱感"，于是卡片里加了可展开的算式：

```
你的竞争力 0.65 − 项目门槛 0.74 = −0.09
扣分：TOEFL 低于门槛 103 −0.05
最终差值 −0.09 → 档位（≥0.10 保底 / ≥−0.02 匹配 / ≥−0.18 冲刺）
```

以及一句百分位：**"在 1117 个项目中，你的竞争力高于 55% 的录取门槛"**（用 `d < score` 的项目数占比算出来）。

### 2.4 政策表述的准确性

三处曾被指出写错或说得太满，都已修正：

| 原表述 | 问题 | 改成 |
|---|---|---|
| "STEM 专业可享 36 个月 OPT" | 把"专业名称"当成资格依据 | 说明 12 个月常规 OPT + 最长 24 个月延期；是否 STEM 以 DHS 名单和 CIP 代码为准，雇主需满足 E-Verify |
| "推荐信晚一天，整份申请就作废" | 过于绝对，各校补交政策不同 | 改为"材料应提前准备，部分项目允许一定范围内补交，以官网为准" |
| 医保"另行计算" | 不给具体数，预算不完整 | 列为独立费用项，可逐校填写实际值；附 6 项核对清单（保费/Waive/免赔额/OOP 上限/校外保险/覆盖期） |


### 2.5 让卡片回答四个问题

原来的卡片是数据罗列。后来改成每张卡必须回答：

1. **为什么推荐我？** → 3 条理由（转码友好 / 课程匹配 / 科研可写 / 预算内 / 排名）
2. **我有哪些短板？** → 3 条风险（缺先修 / 语言不够 / 超预算 / 强制 GRE / 学费估算）
3. **这个项目要多少钱？** → 分年 + 全程
4. **下一步做什么？** → 看档案 / 加入清单 / 核对官网

首页还加了一张**背景画像卡**：本科专业、均分、目标方向、入学时间，下面直接分「申请优势」和「需要补强」两栏——这两栏是从六维分数里推出来的，不是写死的。

以及一个**一键生成最优组合**：选 6/8/10 所，按 2:4:2 自动分配冲刺/匹配/保底，避开同校重复，预算内的优先。


### 2.6 进度看板与课程缺口

- **申请进度看板**：清单里每所学校 4 个阶段（个人陈述 / 推荐信 / 语言送分 / 正式提交），打勾后整体完成度实时计算。
- **课程缺口报告**：对照 9 项常见 CS 先修（线代/概率/微积分/离散/数据结构/编程/操作系统/网络/数据库），输出"已具备 X/9"和按优先级排序的补强清单。
- **本地存储提示**：清单页顶部常驻一句"数据只存在这台设备的浏览器里"，并指向导出/导入备份。


### 2.7 跨专业专项评估

最后一页是给"物理/数学/电子转 CS·AI"的人做的。把"能不能跨申"拆成 7 个可回答的问题：

| 评估项 | 系统回答什么 |
|---|---|
| 本科背景 | 你的专业在项目眼里算不算相关 |
| 数学基础 | 线代/概率/微积分覆盖了几门 |
| 编程基础 | 只会 Python 够不够 |
| CS 基础 | 数据结构/算法/操作系统/网络缺哪些 |
| 科研经历 | 现有项目能不能支撑 AI 申请 |
| 项目选择 | 库里有多少项目不要求 CS 本科 |
| 申请策略 | 该主申 AI/DS 还是传统 MSCS |

每一项给出「满足 / 待加强 / 需补」三档结论，并附一句具体动作（例如"刷 100–150 道算法题 + 用 Python 复现 1 个 ML 项目"）。底部还会列出对跨专业更友好的项目（优先 `conv` 标记与宽松先修）。

## 3. 第三轮：接真实数据（一半成功，一半失败）

用户要求"接入国外网站，数字准确"。我试了四条路。

### 3.1 成功：生活费

**MIT Living Wage Calculator** 是静态 HTML，可以直接抓。每个县一个页面，含分项年成本（Food / Housing / Transportation / Civic / Internet / Medical）。

```
学生口径 = Housing×0.6 + Food + Transportation + Internet
```

Housing 打六折对应两人合租；不含医保（由学校保险覆盖）。最终覆盖 **39 个县**，每个县都记录了 FIPS 编号和原始页链接。

### 3.2 失败：学费

这是整个项目最大的短板，试了三种方法都不行：

| 方法 | 结果 |
|---|---|
| 直接 curl 大学费率页 | 多数是 JS 空壳（Georgia Tech 48KB 页面只解析出 2.8KB 文本） |
| headless Chrome 渲染 | 能拿到 DOM，但费率藏在子页/PDF 里 |
| 美国教育部 IPEDS 数据集 | 只有 2023–24，且是"全校研究生平均 + 公立州内价"，用作项目级会低估一半 |

**最典型的坑**：CMU 官网 Heinz 学院那个 `$29,570` 其实是**每学期**，乘 2 才是年费。自动抓取如果不懂语义，会产出"看起来精确、实际错一倍"的数字。

结论：学费保留为**区间参考**，只有 4 条按官网核实过。

### 3.3 部分成功：录取数据

从各校 FAQ / Class Profile 页面手工核实了 4 条：

- **CMU SCS**：录取者 TOEFL 多在 105–114，最终截止 12/9
- **USC Viterbi**：官网明确无最低 GPA / 无最低 TOEFL
- **UIUC**：校区最低 GPA 3.0/4.0
- **Cornell**：研究生院要求各单项最低分、IELTS 7.0

其余 26 所 Top 30 的 Class Profile 抓不到（JS 渲染或 403）。

## 3.4 数据可信度分级

用户提出一个关键问题：**1117 条记录，不等于 1117 条核实过的数据。**

确实如此。只有 4 条（现在 3 条通过校验）是从官网确认的，其余全是推算。所以建立了四级标签，并且让标签有行为含义：

| 标签 | 含义 | 处理方式 | 数量 |
|---|---|---|---|
| 官方已核实 | 已从项目官网确认 | 可用于正式筛选 | 3 |
| 第三方数据 | 来自可信统计平台 | 已标明来源 | 0 |
| 估算数据 | 按学校/项目特征推算 | 不参与精确判断 | 1114 |
| 待更新 | 过期或无法确认 | 提醒用户核实 | 0 |

项目库顶部有一条常驻统计条，直接写"全库 1117 条 / 已核实 3 / 估算 1114 / 待更新 0"，并附一句"记录数 ≠ 核实数"。

这样用户看到的第一眼就知道：这个库有多大是真的，有多大是估的。

## 4. 第四轮：标签体系

给每个项目打四类标签，全部**有判定标准**，不是拍脑袋：

| 标签 | 标准 | 数量 |
|---|---|---|
| 转码友好 | 明确面向非 CS 背景 | 11 |
| 实习友好 | co-op / 实习是毕业要求 / 就业导向学位 | 10 |
| 申博友好 | 论文型或研究导向 | 23 |
| CS 先修 | 不要求 / 需补先修 / 需 CS 本科 | 8 / 23 / 36 |

**关键教训**：第一版按"城市就业机会"标了 38 个实习友好，等于没标。后来收紧到"有结构性理由"的 10 个——纽约、湾区当然好找实习，但那是地理位置带来的，不是项目设计。

## 5. 第五轮：扩库（100 校 × 35 专业）

用户要"US News 前 100 + 所有专业"。写了生成器 `tools/gen_programs.py`：

1. **学校表**：105 所，每所有排名、城市、州、公私、类型（tech / big / public / city）、县 FIPS
2. **专业表**：35 个方向，每个有先修等级、典型截止、学制、难度调整、学费系数
3. **两轮生成**：
   - 第一轮：每校生成核心方向（cs / ds / mba / ee）
   - 第二轮：其余方向按"每个方向最多 22 所"摊开
4. **去重**：和已有的 67 条详细项目按 (学校, 专业) 比对

学费按「私立/公立 × 排名档位」给区间，并记录 `tlo` / `thi`，UI 上显示为 `$95,000 ±9,000`。

**这里踩了一个坑**：第一版每校只取前 7–9 个方向，导致药剂、护理、法学、新闻等 16 个方向**根本没有数据**，但界面上 35 个筛选按钮都在。用户点进去是空的。后来改成两轮生成才修好。

## 6. 第六轮：交互补全

按用户提的意见逐个加：

- **我的清单**：收藏、按截止日排序、倒计时、打印、CSV、备份
- **并排对比**：选 2–3 个，13 个维度横向比
- **细粒度筛选**：截止月 / GRE / 学制 / RA-TA
- **个性化倒排**：以清单里最早的截止日为锚点倒推，导出 .ics 日历
- **风险清单**：硬性先修、最早截止、语言不达标、误差最大
- **反向选校**：先定预算/地区/留美，再看剩什么

**每次加功能都要跑一遍冒烟测试**，因为功能之间会互相踩。

## 7. 第七轮：部署

用户要"外网可访问"。

| 尝试 | 结果 |
|---|---|
| cloudflared 隧道 | 注册成功，但数据回程被沙箱代理掐断（边缘 522） |
| pinggy | 能用，但浏览器会先弹「Caution」警告页 |
| localhost.run | 能用，但空闲约 1 分钟就断开 |
| bore.pub | 能用，无警告页，但是 http |
| **Netlify** | ✅ 最终方案 |

中间还发现：页面 503KB，隧道限速下要 62 秒才传完，浏览器多半超时。于是写了个 **gzip 静态服务器**（503KB → 68KB），加载降到 2 秒。

最终部署：Netlify API（`POST /sites` 建站 + `POST /sites/{id}/deploys` 传 zip），地址 https://us-masters-planner.netlify.app 。

## 8. 踩过的坑（都真实发生过）

1. **CMU 学费是每学期**——差点把 $29,570 当成年费
2. **删导师库时误删了整个清单模块**——正则范围过大，函数没了但调用还在，`init` 在中途抛错，后面所有绑定都不执行
3. **`id="fGre"` 冲突**——表单里的 GRE 选择和新加的筛选下拉重名，`getElementById` 拿到的是第一个
4. **`[hidden]` 失效**——`.cmp-modal{display:flex}` 覆盖了 `hidden` 属性，弹窗一直显示
5. **表格 `min-width:880px`**——移动端短清单被挤出屏幕，数值跑到右边界外
6. **星标点击整页重渲染**——连点第二下就失效（元素被替换了）
7. **筛选按钮点一次就死**——每次重渲染替换了节点，绑在旧节点上的监听器随之消失（改成事件委托）
8. **35 个方向一半没数据**——生成时只取前 N 个方向

## 9. 技术决策记录

**为什么单文件 HTML？**
零依赖、零构建、可以直接双击打开，也可以直接丢到任意静态托管。代价是文件越来越大（现在 500KB），但换来了"永远能跑"。

**为什么用 localStorage？**
没有后端。所有状态（清单、改过的学费、排名、筛选）存本地，导出/导入 JSON 做迁移。

**为什么学费用档位估算而不是编造精确值？**
因为抓不到。明确标注"估算 + 误差区间"比给一个假精确的数字诚实。

**为什么不打包成 React？**
没有构建步骤意味着任何人拿到文件就能改，不需要 `npm install`。对于一个个人工具，这比工程化更重要。

## 10. 验证方法

每改一轮都做三件事：

1. **headless Chrome `--dump-dom`**：跑 JS 后检查渲染结果（比如"清单里有几条"、"筛选后剩几个"）
2. **截图**：桌面 1220px + 移动 390px（用 iframe 强制视口，因为 Chrome 最小窗口 500px）
3. **冒烟测试**：写一段注入脚本，模拟点击、读 DOM、把结果写进 `document.title`

比如验证反向选校：
